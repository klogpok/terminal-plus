# DevPanel 0.3.0: see when a build breaks

Install it over 0.2.0: the installer replaces the app, and your Workspace, Local Configs and UI Language stay where they are, in `%APPDATA%\DevPanel`.

## New

- **Build Error mark.** While a Service is starting, running or unhealthy, DevPanel watches its output for the build summary of nx, webpack, Angular CLI, `tsc --watch`, `nest start --watch` and vite-plugin-checker. When the last build failed, the Service's dot turns red with "!", and its tooltip says "The build has errors, see the terminal". A collapsed Repo lists the Service under its attention mark. The next successful build, a Stop or a restart takes the mark off. The Status does not change: a Service with a Build Error is still running.
  - Another tool? Add `errorPattern` (a regular expression) to the Service in the config: a matching line marks the build as failed, and a line matching the Service's `readyPattern` marks it as fixed.

# DevPanel 0.3.0: видно, когда сборка сломалась

Устанавливайте поверх 0.2.0: установщик заменит приложение, а Workspace, Локальные конфиги и Язык интерфейса останутся на месте, в `%APPDATA%\DevPanel`.

## Новое

- **Ошибка сборки.** Пока Сервис запускается, работает или нездоров, DevPanel следит в его выводе за итоговыми строками сборки nx, webpack, Angular CLI, `tsc --watch`, `nest start --watch` и vite-plugin-checker. Если последняя сборка не прошла, точка Сервиса становится красной с «!», а подсказка говорит «В сборке ошибки, смотрите терминал». Свёрнутое Репо показывает такой Сервис под своей отметкой внимания. Отметку снимает следующая успешная сборка, «Стоп» или перезапуск. Статус не меняется: Сервис с Ошибкой сборки по-прежнему работает.
  - Другой инструмент? Добавьте Сервису в конфиге `errorPattern` (регулярное выражение): совпавшая строка помечает сборку как упавшую, а строка, совпавшая с `readyPattern` Сервиса, — как исправленную.
