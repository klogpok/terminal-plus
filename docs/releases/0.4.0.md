# DevPanel 0.4.0: check a branch from its worktrees

Install it over 0.3.0 (or 0.2.0): the installer replaces the app, and your Workspace, Local Configs and UI Language stay where they are, in `%APPDATA%\DevPanel`.

## New

- **Branch Check.** The new "Branches" button in the header lists every branch that has a git worktree in any of your Repos, with the Repos it spans. "Check" switches each of those Repos to its worktree on the branch and restarts there the Services that were running (all of them when none was). Repos without the branch keep running as they are, so a shared backend on `master` keeps serving the feature's frontend. While a branch is checked, the header shows "Checking ⎇ <branch>"; "Back to main" runs every Repo from its own folder again.
  - DevPanel only finds worktrees (`git worktree list`); it never creates or removes them. Worktrees in detached HEAD are not listed.
  - A worktree with its own `.devpanel.yml` runs as that file describes; otherwise the Repo's Local Config is used. If a Service that was running is not in the worktree's config, or does not come up, DevPanel says which.
  - New Claude Code and terminal Sessions, "Open folder" and "Install dependencies" use the worktree too.
  - After DevPanel restarts, every Repo runs from its own folder.
- **Folder switcher.** The branch under a Repo's name is now a button: it switches just that Repo between its own folder and its worktrees. A "Worktree" mark shows while a Repo runs from one.

## Changed

- The header wraps onto a second line in a narrow window instead of running off the edge.

## Русский перевод

# DevPanel 0.4.0: проверка ветки из её worktree

Устанавливайте поверх 0.3.0 (или 0.2.0): установщик заменит приложение, а Workspace, Локальные конфиги и Язык интерфейса останутся на месте, в `%APPDATA%\DevPanel`.

## Новое

- **Проверка ветки.** Новая кнопка «Ветки» в шапке показывает каждую ветку, у которой есть git worktree в каком-либо из ваших Репо, и Репо, в которых она есть. «Проверить» переключает каждое из этих Репо на его worktree с этой веткой и перезапускает там Сервисы, которые работали (все, если не работал ни один). Репо без этой ветки продолжают работать как есть, так что общий бэкенд на `master` продолжает обслуживать фронтенд фичи. Пока ветка проверяется, в шапке видно «Проверка ⎇ <ветка>»; «Вернуть на основную» снова запускает каждое Репо из его собственной папки.
  - DevPanel только находит worktree (`git worktree list`), но никогда их не создаёт и не удаляет. Worktree в detached HEAD в списке не показываются.
  - Worktree со своим `.devpanel.yml` запускается так, как описано в этом файле; иначе используется Локальный конфиг Репо. Если работавшего Сервиса нет в конфиге worktree или он не поднялся, DevPanel скажет, какой именно.
  - Новые Сессии Claude Code и терминала, «Открыть папку» и «Установить зависимости» тоже работают в worktree.
  - После перезапуска DevPanel каждое Репо снова работает из своей папки.
- **Переключатель папки.** Ветка под именем Репо теперь кнопка: она переключает только это Репо между его собственной папкой и его worktree. Пока Репо работает из worktree, рядом видна отметка «Worktree».

## Изменено

- В узком окне шапка переносится на вторую строку, а не уходит за край.
